## 一、一页速览

1. 本次审计对标《通用分支开发框架 V2.0（通用分支版）》逐域盘点八大领域，核心结论是：**框架要求的"分支体系"目前基本空白**——总谱/分谱/支谱三级树、全局唯一编码（HAO-）、分支创建/合并/迁移/统计等核心能力均未开工。
2. 八域合计 **P0 缺口 46 项、P1 缺口 28 项、P2 缺口 11 项**，另有 25 项部分达标、22 项已达标；缺口高度集中在分支域（10）、世系域（15）、入谱域（7）、权限与文化域（8），称谓计算与数据交换两域无 P0。
3. 好消息是地基牢靠：双人审核链、公示机制、审计留痕（≥1 年）、首屏性能（1.21s ≤ 1.5s）、称谓计算引擎等均已达标并有测试背书，**不需要推倒重来**。
4. 按工作量折算，距 V2.0 通用分支版完整对齐约需 **4-6 个月全职开发**（估算 6-7 人月：全栈 2-3 人、前端 2 人、测试 1 人、族史委顾问 1 人，覆盖 R26-R38 共四个阶段）。
5. 46 项 P0 中约 38 项建议**必须纳入 MVP**，约 5 项建议降级 P1，约 3 项需族史委**先行裁决**方可启动（见第二、四节）——裁决不落地，MVP 无法开工。

## 二、MVP 范围划定建议（P0 共 46 项归组）

**结论先行**：建议按「必做 / 降级 / 待裁决」三档划定 MVP；必做档聚焦"分支地基＋数据地基＋入谱流程＋安全＋文化"五条主线。

### 档一：建议纳入 MVP（必做，约 38 项）

| 域 | 必做内容 | 一句话理由 |
|---|---|---|
| ① 分支域（10 项全保） | 三级谱系 schema（层级/父编码/唯一编码）＋HAO 编码自动生成＋分支四大功能（创建/合并/迁移/统计）云函数＋分支管理前端页 | V2.0"通用分支版"的立身之本，其余一切分支能力的地基 |
| ② 世系域（15 项全保） | 成员表 P0 字段补齐（字号别名/兄弟姐妹序次/出生逝世地/墓葬/职业/来源标注/置信度/版本号等）＋关系表升级为五类关系（含过继子类/起止日期/审核人）＋成员编辑工作流（编辑＋追加证据＋置信度＋版本递增闭环） | 数据地基；关系表枚举过时已致生产写入通不过校验，部分字段被代码引用形成"悬空" |
| ④ 入谱域（7 项全保） | 六类入谱语义建模（新生儿/迁入/迁出/过继/归宗/OCR 批量）＋证据链字段强制校验＋前端入谱提交页（清理死路由）＋公示期口径修正 | 核心业务流程目前六类中仅通用审核链可用（≈1/6），迁入/迁出/过继/归宗四类族务刚需无处提交 |
| ⑧ 权限部分（4 项） | 新增支长角色＋分支上下文写权限（编辑本支=支长＋、他支=族史委＋）＋创建分支=房长＋、合并分支=族史委＋门禁 | 越权修改他支数据的安全底线；不补则分支体系形同虚设 |
| ⑧ 文化部分（4 项） | 宋村文化四大分区结构化入库（千年地标/迁居时间轴/郝光甲/宋村惨案）＋首页「宋村·根脉」卡片挂载 | 文化传承是本项目立项的核心诉求，数据目前仅存研究文档、散佚风险最高 |
| ③ 字辈域（2 项） | 字辈集合重构为主表（消除双轨存储与字段口径矛盾，含字辈诗渊源记录）＋核心业务集合补齐来源标注字段 | 字辈是谱名生成与世代挂接的依据；"每条数据可溯源"是家谱可信度的纪律红线 |

### 档二：建议降级 P1（约 5 项，随第二/四阶段交付）

| 条目（域） | 降级理由 |
|---|---|
| 出生年份→世代自动匹配算法（③） | 便利性功能：MVP 期由管理员录入时人工指定世代即可，算法排 R28-R30 |
| 字辈用尽续拟审批流（③） | 字辈诗通常数十代、短期用尽概率低，且依赖决策点③文本先行；MVP 仅预留工单模板 |
| 地理迁徙图（⑤） | 依赖腾讯地图 API 申请与地图开发，属展示增强；迁徙数据先随世系/分支字段落库，可视化后补 |
| 直系图/时间轴 UI 挂载（⑤） | 底层算法已就绪，属低风险收尾，与迁徙图同批交付，不影响 MVP 主流程 |
| OCR 老谱批量入谱整链（④） | 依赖腾讯云 OCR 开通与老谱照片整理，Excel/CSV 导入通道可兜底，排 R36 AI 增强轨 |

## 四、需族史委裁决的 5 个决策点

以下 5 点均阻塞 MVP 数据或流程定稿，建议本次评审会逐项拍板：

| # | 决策点 | 背景（现状） | 需裁决内容 | 不裁决的后果 |
|---|---|---|---|---|
| ① | 公示期是否统一 7 天 | 框架口径"公示 7 天"；系统默认 0 天（复审通过即生效，不公示） | 全类统一 7 天？还是分类差异化（如新生儿/过继公示 7 天、迁出仅记录免审）？ | 入谱域上线即需定稿口径，涉及族内异议窗口的合规性 |
| ② | 支长/房长角色任命流程 | 系统现有角色缺"支长"，"编辑本支=支长＋"无法落地 | 明确支长与房长的职责边界、产生方式（推选/指定）、由谁在系统内授予与备案 | 权限矩阵无法配置，审核链第一环悬空 |
| ③ | 宋村字辈诗权威文本 | 框架 8.1 节明示"字辈诗：待族史委提供"；字辈主表重构在即 | 提供 ≤50 代字辈诗全文及渊源说明（朝代/编撰人/文献出处） | 字辈重构（R26-R27）无 seed 数据，谱名自动生成受阻 |
| ④ | 文化数据权威版本审定 | 郝光甲（1838 年武进士第一，引自《清史稿》）、宋村惨案（1937-10-12，遇难近 200 人）等表述仅存研究文档 | 逐条审定权威口径与表述分寸（尤其惨案遇难人数等敏感史实的措辞） | 四大文化分区无法结构化入库，首页「宋村·根脉」无法挂载 |
| ⑤ | **分支编码规则（开发侧裁决 A）** | R26 采用：**HAO-NNNN[-NN]…层级序列码**（总谱 HAO-0000 / 分谱 HAO-0000-01 / 支谱 HAO-0000-01-03） | 是否叠加中文可读别名（如“宋村”）？**裁决：A 方案——纯 HAO- 序列码，不叠加别名。** | 序列码天然唯一/层级自解释；可读性由前端显示层承担（`name` + `region`），后续若需 alias 字段可 additive 扩展。
