"generationChar": ["string", "null"],       // 字辈字（由 generations 字辈表匹配）

#### 3. Generation.alignCheck（框架 §5.1）
- Action: `generation.main({action:'alignCheck', generation, genealogyName, surname, generationChar})`
- 输出: `{aligned:true/false/null, expectedChar, actualChar, beyondPoem, note}`
- 语义：谱名字辈字与 `settings.generation_chars` 实时比对；超字辈表时返回 `beyondPoem=true`，提示走族议会续拟流程（框架§4.4）

#### 4. Branch.merge 增强（框架 §5.3）
- 四维匹配：`genealogyName + generation + fatherGenealogyName(lifespan.birth)`（母名暂缺，以生年替代）
- 容错：无谱名成员自动跳过（防空键误报）
- 输出: `mergeReport: {scannedFrom/scannedTo, conflictCount, conflicts[{memberId,genealogyName,generation,matchedCount}], strategy: 'keep_both_source_tags_pending_review'}`
- 审计: detail 携带 `conflictCount`

## 🔍 待议事项（需族史委裁决/后续 Sprint 决策）

### 1. 分支编码格式选择（框架 §2.3 决策点⑤）

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| **可读中文方案** `HAO-冀-赵县-宋村-001` | 人工可理解、带地域语义 | 长度不可控、非 ASCII、数据库检索效率略低 | 用户友好 ⭐⭐⭐⭐ |
| **层级序列码方案** `HAO-0000-01-03` | 长度固定、全局唯一、检索快、无中文字符依赖 | 无地域语义、人工理解弱 | 工程优先 ⭐⭐⭐⭐⭐ |

**当前实现**: 层级序列码（schema pattern=`^HAO-[0-9]{4}(-[0-9]{2})*$`），已在 schema 注释中标注「评审决策点⑤：可读中文别名待族史委裁决」。

**建议**: 采用「主码读序列码 + name 字段存中文名」混合策略——数据库用 HAO-0000-01 作唯一键，前端展示用 name+region 拼接。若族史委强烈要求可读编码，可改 pattern 但需评估现有索引性能。

### 2. 入谱类型模型扩展（框架 §4.5）

entry.submit 目前 type 仅为录入渠道（OCR/EXCEL/MANUAL）。框架要求的六种入谱场景（新生儿/迁入/迁出/过继/归宗/OCR）尚未建模。

**建议改动**:
1. 增加 `type="ENTRY_KIND"`，允许值：`NEWBORN`, `MIGRATION_IN`, `ADOPTION`, `RETURN`, `MIGRATION_OUT`
2. payload 扩展字段：
   - `sourceBranchCode`（原分支代码，迁入用）
   - `proofSourceTag`（证明来源标注）
   - `proofDocumentId`（证明文件 ID，documents/schema 关联）
3. 审核链：所有 ENTRY_KIND 均走「双人审核→公示期」流程（保持现有一致性）

**改动面**: validatePayload + submitEntry，预计 10~20 行代码 + 2~3 新单测。不影响现有手动/Excel/OCR 提交路径。

### 3. members.version 乐观锁策略

新增 version 字段用于更新时乐观锁检测（防止并发冲突）。待定义递增规则：
- **选项 A**: 每次 update → version++（标准 optimistic concurrency control）
- **选项 B**: 仅在检测到其他用户编辑冲突时 version++（lazy increment）

建议采用 **选项 A**（简单可靠），配合前端版本提示（冲突时显示“该记录已被他人修改，请刷新后重试”）。

### 4. DNA 对接预留字段

dna_records.schema.json 已存在（占位）。V3.0 对接需补充：
- yHaplotype / mtHaplotype（单倍群）
- ethnicityEstimates（族群比例对象）
- cMMatches（亲属匹配数组：{relative, cM, predictedRelationship}）
- consentGranularities（隐私授权粒度：公开/仅管理员/仅匹配可见）

建议 V3.0 Phase 1 前完成详细 API 设计规范（OAuth2 同步 23andMe/WeGene 原始数据文件 + 解析）。
